# Token logo delivery correction

The public Orbit frontend previously loaded full-size Ember images directly in each visitor's browser. A failed request permanently switched the mounted avatar to initials. The user's iPhone screenshot showed this for every hero token. Thirty independent upstream checks with desktop/iPhone headers succeeded, so a particular carrier, browser restriction or upstream outage is not established as the original cause.

The shared avatar now uses `/api/token-image?source=...` on the application's origin. Both hosted and local API adapters serve the same handler. Sources must be approved HTTPS providers with content-addressed image paths. The handler follows no redirects, forwards no caller credentials, bounds reads to 4 MB and 6 seconds per gateway, rejects non-raster/invalid bodies, and decodes at most 16,777,216 pixels. Sharp generates a fixed maximum 160 px WebP thumbnail with metadata removed. A fallback gateway can retrieve only the identical content ID. There is no symbol/name-to-logo list and no dated token lineup in production code.

Successful thumbnails have bounded in-process caching/coalescing and public CDN cache headers; failures are not cached. Initial load plus two delayed retries is the avatar limit. Changing mint/source resets state, reconnecting restores failed avatars, and timers/listeners are cleaned up. Hero and detail logos load eagerly; lower rows remain lazy. The decorative spark is SVG to avoid iOS emoji substitution.

Validation: the full 228-test suite passes, including 13 new relay/URL/security tests; TypeScript and production build pass. An independent review passed 17 relay assertions and desktop/mobile browser inspection with external images blocked. All ten hero logos and all ten list logos loaded from same-origin thumbnails, with maximum dimensions 160 px. The observed ten-thumbnail payload was 45,818 bytes versus 8,450,388 original bytes (observations may change). Browser tests use Chromium desktop and iPhone viewport/UA emulation, not a physical iPhone Safari test.

One-PC ownership: root owns the API/image contract, integration and deployment; interaction_fixes owns the Avatar/spark changes in a separate worktree; review_finish independently reviews source and rendered output. Local raw evidence, screenshots and actual deployment verification are retained in `outputs/EMBER10-logo-review` beside the repository. Logo delivery does not change market ranking, selection, funded membership, payout policy or signing controls.
